**Airship — воспроизводимая RL-среда обучения с подкреплением для ИИ-аудитора финансовой отчётности.**  
Среда генерирует реалистичные синтетические компании с бухгалтерскими ошибками, предоставляет изолированный интерфейс инструментов расследования (`list_records`, `get_record`, `get_document`, `calculator`, `submit`) и строго оценивает доказательную базу выводов.

## ⚡ Ограничения среды (Strict Zero-Leak Constraints)
- **Полная автономность:** Без сетевого доступа (`--network none`), без платных API, без GPU.
- **Минимальный стек:** Python 3.11+, стандартная библиотека + `pydantic==2.10.4`, `numpy==2.2.1`.
- **Бюджет:** < 2 CPU, < 4 GB RAM, < 60 секунд на эпизод, лимит 100 шагов.
- **Синтетические данные:** Все контрагенты, счета, суммы и документы полностью вымышлены.
- **Информационная безопасность:** Закрытые файлы (`truth.json`, `provenance.json`, `seed`) изолированы и **не утекают** в observations, пути, сообщения об ошибках и логи.

## 🚀 Быстрый старт

### Единая команда проверки (Регламент хакатона)
Запуск полного цикла проверки (67 тестов + генерация 20 эпизодов + прогон 4 политик + вывод таблиц):
```bash
./scripts/check.sh
# или через make
make check
```

### Запуск в изолированном Docker-контейнере (без сети)
```bash
# Сборка образа
docker build -t airship:latest .

# Запуск проверки с отключенной сетью
docker run --rm --network none airship:latest ./scripts/check.sh
```

### Интерактивное пошаговое демо (п. 09 регламента)
Показ реального процесса расследования одного эпизода агентом с цветным терминальным оформлением:
```bash
make demo
# или
python3 scripts/cli.py demo
```

### Терминальный интерфейс (Airship CLI & Режим "Человек-Аудитор")
Проект оснащён автономным CLI-модулем с Unicode-таблицами, индикаторами прогресса и цветными плашками (без внешних зависимостей):
```bash
# Просмотр справки по всем командам CLI
python3 scripts/cli.py --help

# Интерактивный режим расследования человеком (Human Auditor Mode)
make play
# или
python3 scripts/cli.py play train_ep_03

# Просмотр книги проводок и инвойсов любого эпизода
python3 scripts/cli.py inspect train_ep_03 --table ledger --limit 10

# Бенчмарк 4 политик с анимированным прогресс-баром
make benchmark
```

## 🎯 Поддерживаемые типы нарушений (Ground Truth)

1. **`E1 duplicate_accounts`:** Дублирование бухгалтерских записей хозяйственной операции в книге при наличии единственного первичного инвойса.
2. **`E2 partial_payment`:** Оплата проведена полностью в платёжном поручении, но в книге разнесена лишь частично.
3. **`E3 wrong_fx_or_date`:** Операция в иностранной валюте отражена по искажённому курсу вместо официального курса из `fx.csv`.
4. **`E4 period_misclassification`:** Ошибка признания отчётного периода (операция за пределами периода отнесена в текущую книгу).
5. **`X1 partial_fx_period_boundary`:** Взаимодействующий сценарий: неполный платёж в валюте на границе отчётного периода.
6. **`X2 duplicate_and_period`:** Взаимодействующий сценарий: дублирование проводки в сочетании с ошибкой периода.

## ⚖️ Скоринг и награда

### Сопоставление (Bipartite Matching)
Вывод признаётся **True Positive (TP)** при одновременном выполнении условий:
- Совпадение типа ошибки (`type`) и валюты (`currency`).
- Каноническое равенство множеств `affected_ids` (порядок не важен).
- Сумма расхождения в пределах допуска: $|claimed - expected| \le 1$ minor unit.
- Доказательства `evidence_ids` содержат полный набор из `acceptable_evidence_sets`.

### Формула терминальной награды:
$$\text{Return} = \text{clip}\left(2 \cdot F1 - 1.0 - 0.002 \cdot \text{steps}, -1.0, 1.0\right)$$

*При нарушении схемы отчёта или исчерпании лимита шагов без отправки выставляется штраф `-1.0`.*
